How it works

Two-phase
scroll experience

Phase 1 scrubs a 4K video using currentTime set directly from window.scrollY. As you scroll down, the phone rotates through its hero animation frame by frame.

Phase 2 begins when the video reaches its last frame. A static photo crossfades in, pixel-locked to the video, then the phone slides upward (the "garage door") as the next content section reveals beneath it.

Key formula: S = Math.max(W / VIDEO_W, H / VIDEO_H)
Every asset is scaled by S so it covers the viewport at all sizes. Change one number, everything stays aligned.

Design Panels

Four live
design controls

Shadow — Tune the drop shadow's blur radius, vertical offset, color, and opacity. Changes render in real time on the hero phone.
Sequence — Adjust the video scrub speed multiplier (1× to 6×). Higher values make the animation feel snappier.

ANIMATE Driver

Principle-for-Mac
light

The Driver lets you animate any element over scroll — without touching code. Set a value at one scroll position, set another at a different position, and the system interpolates smoothly between them.

Scroll position shown in px at top right of panel. This is the key: keyframes are stored at exact pixel positions.
Track selector — pick which element to animate. The count badge shows how many KFs that track has.
Sliders — X, Y, Scale, Rotate, Opacity. Drag to preview live, then hit SET KF to record that state at the current scroll position.

Keyframe Workflow

Six steps,
smooth animation

1
Click the circles pill
Left edge of screen — panel slides in. You're now in Animate mode.
2
Select a track
Panel A, B, C, or Closer Photo. Each track is independent.
3
Scroll to start position
e.g. 2400px where the triptych first enters view. Adjust sliders to the starting state you want.
4
Hit ◆ SET KF
Button flashes cyan. Keyframe recorded at current scrollY.
Saved to localStorage
5
Scroll to end position
e.g. 5800px. Move sliders to the end state.
6
Hit ◆ SET KF again
Now scroll between the two positions — the element animates smoothly with easeInOut cubic.

Pro tips
→ Click a KF row in the list to jump sliders to that exact state.

→ KFs survive page refresh (stored in localStorage as drvKFs3).

Below-Hero Content

Three panels,
one image

All four animatable elements share a single source image — phone_endframe.jpg. Each panel uses a different object-position and transform-origin to show a distinct crop, so the triptych reads as three unique shots.

Panel A — Camera bump detail. Origin 23% 28%, default scale 2.6×. Zoomed deep into the triple-lens cluster.
Panel B — Full phone back, nearly 1:1. Origin 50% 42%, scale 1.06×. Serves as the "establishing shot" of the three.
Panel C — Extreme close-up into the upper-left corner of the device. Origin 34% 12%, scale 4.8×.
Closer Photo — Full-bleed in the adjacent section. Default scale 2.2×. Animate this track independently from the triptych panels.

Deployment

100% static.
No server needed.

The entire demo is plain HTML + CSS + JavaScript — no build step, no npm, no server. Upload the files directly via FTP or a file manager and it runs immediately.

hero.mp4 is the largest file. Make sure your host allows large file uploads (GoDaddy shared hosting: 500MB limit). The video should stream from the same server without a CDN for local testing.
No .htaccess needed. All links are relative. assets/hero.mp4 will resolve correctly as long as the folder structure is preserved.
Keyframes are client-side only. localStorage data is per-browser. Share your KF config by exporting it as JSON from the browser console: localStorage.getItem('drvKFs3').
Performance tip: serve hero.mp4 with the Content-Range header enabled (most shared hosts do this by default). This allows Safari to scrub video without downloading the entire file first.
